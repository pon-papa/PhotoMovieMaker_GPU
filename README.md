# PhotoMovieMaker GPU

Windows 11 用。**写真フォルダーから、パン＆ズーム付きの MP4 スライドショー（記念映像）を作る**小さな GUI アプリです。

- **完全にローカルで動きます。** 写真・BGM を外部へ送信しません（通信するのは、最初の setup でパッケージを取得するときだけ）
- **元の写真・BGM は読むだけ。** 名前の変更・移動・削除・上書きをしません
- NVIDIA の GPU があれば NVENC で、無ければ CPU で書き出します。どちらでも動きます

バージョン: **v0.2.0**（[変更履歴](CHANGELOG.md)・[リリースノート](RELEASE_NOTES_v0.2.0.md)）

## まず使う

1. [Releases](https://github.com/pon-papa/PhotoMovieMaker_GPU/releases) から `PhotoMovieMaker_GPU_v0.2.0_Windows.zip` をダウンロードする
2. ZIP を**すべて展開**する（置き場所は自由。ドキュメントなど、自分で書き込める場所へ）
3. 展開したフォルダーの中の **`setup.bat`** をダブルクリックする（最初の 1 回だけ。数分かかります。インターネット接続が必要）
4. **`run.bat`** をダブルクリックする（アプリが起動します）
5. 「写真フォルダー」で写真の入ったフォルダーを選ぶ（必要なら「BGM区間を追加」で曲も選ぶ）
6. **「MP4を作成」** を押す

必要なのは **Windows 11** と **Python 3.11〜3.13** だけです。Python が入っていなければ、
先に [python.org](https://www.python.org/downloads/windows/) から入れてください（インストーラーの標準の構成のままで構いません）。

うまくいかないときは、同じフォルダーの **`diagnose.bat`** を実行すると、何が足りないかが表示されます（→ [困ったとき](#困ったとき)）。

> **AI による自動編集について**
> このアプリは、写真を選ぶ・並べる・曲を選ぶ、といった判断を自動ではしません。画面で人が決めます。
> 作者の記事などで紹介している「AI が写真と BGM を選んで作品を組み立てる」流れは、このアプリの CLI を
> 作者の実験用の AI 連携環境から呼び出して行ったもので、**ZIP をダウンロードしただけでは動きません**
> （→ [開発者向け](#開発者向けai自動化から使う)）。

## 動作環境

| | |
| --- | --- |
| OS | Windows 11 |
| Python | 3.11 / 3.12 / 3.13 に対応する作りです。**動作を確認したのは 3.13**（Microsoft Store 版 3.13.14）。3.11 / 3.12 は未確認です |
| GPU | 不要。NVIDIA の GPU（NVENC）があれば自動で使います |
| 通信 | `setup.bat` のときだけ（PyPI からパッケージを取得）。アプリの実行中は通信しません |
| 権限 | 管理者権限は不要 |

- `setup.bat` は、アプリのフォルダーの中に `.venv` を作り、必要なパッケージを**その中だけ**に入れます。
  PC 全体の Python には何も入れません。2 回実行しても壊れません
- 動画のエンコードには FFmpeg を使います。**PATH に FFmpeg があればそれを優先し、無ければ
  `imageio-ffmpeg` に入っている FFmpeg を使う**ので、別に入れる必要はありません
- レジストリ・スタートアップ・サービス・Windows の設定は変更しません

作者の確認環境: Windows 11 / Python 3.13 / NVIDIA RTX A2000（NVENC）。1920x1080・30fps・エンコーダ「自動」。

### ZIP を展開するときの注意

インターネットから取得した ZIP や、その中の `setup.bat` / `run.bat` を開くときに、
Windows がセキュリティの警告を表示することがあります。

- 入手元がこのリポジトリの [Releases](https://github.com/pon-papa/PhotoMovieMaker_GPU/releases) であること、ファイル名が `setup.bat` / `run.bat` /
  `diagnose.bat` であることを確かめてから実行してください
- 警告を減らすには、**展開する前に** ZIP を右クリック →「プロパティ」→ 下のほうに「許可する」が
  あればチェックを入れて「OK」→ そのあと展開します
- ZIP が本物かどうかは、Releases に載せている SHA-256 と比べて確かめられます
  （PowerShell で `Get-FileHash PhotoMovieMaker_GPU_v0.2.0_Windows.zip`）
- **SmartScreen やウイルス対策を無効にする必要はありません。** 無効にしないでください

### アプリが作るもの・触らないもの

| | |
| --- | --- |
| 作るもの | 「出力MP4」で指定した場所の MP4 と、その隣の `<動画名>_settings.json`（どの設定で作ったかの記録）。初期値は写真フォルダーの中の `slideshow.mp4` です（変更できます）。**同じ名前のファイルが既にあれば上書きします** |
| 一時的に作るもの | 書き出し中の作業ファイル（Windows の一時フォルダー。終わると消します。中止・失敗でも残しません） |
| setup が作るもの | アプリのフォルダーの中の `.venv` |
| 触らないもの | 元の写真・BGM（読むだけ） |

**アンインストール**は、展開したフォルダーを削除するだけです（`.venv` もその中にあります）。
ほかの場所に設定やデータは残りません。

### 困ったとき

`diagnose.bat` をダブルクリックすると、Python・パッケージ・FFmpeg・NVENC・モデルの状態を確かめて表示します。
何も変更しません。結果にユーザー名やフォルダーの場所は出ないので、そのまま不具合の報告に貼れます。

| 表示・症状 | すること |
| --- | --- |
| 「Python 3.11 から 3.13 が見つかりません」 | Python を入れて、もう一度 `setup.bat` |
| 「まず setup.bat を実行してください」 | `setup.bat` を実行してから `run.bat` |
| 「パッケージを入れられませんでした」 | インターネット接続を確かめて、もう一度 `setup.bat` |
| 「既にある .venv が使えません」 | フォルダーの中の `.venv` を削除して、もう一度 `setup.bat` |
| 診断で「モデル … ありません／中身が違います」 | ZIP が不完全です。Releases から取得し直して、すべて展開 |
| NVENC が「使えません」 | 問題ではありません。CPU（x264）で書き出します |

不具合は [Issues](https://github.com/pon-papa/PhotoMovieMaker_GPU/issues) へどうぞ（個人の小さなプロジェクトなので、対応を約束するものではありません）。
報告には、アプリのバージョン・`diagnose.bat` の結果・表示されたエラーを添えてください。**写真や曲そのものは添付しないでください。**

## 主な機能

- 動画の先頭に**タイトルカード**を自動生成（アプリ内部で作るので、写真フォルダーは汚しません）
- 画像をファイル名の自然順で並べる。**アプリ上で上映順の並べ替えと、使う写真の選択ができる**
- **おすすめ解析**：似た写真をまとめ、技術的に使いやすそうなものへ星を付ける（選別支援）
- 初期値は **8秒ごとに次の写真へ**
- ゆっくりランダム方向へパン
- 徐々にズームイン
- 写真間は初期値1秒クロスフェード
- 縦写真は「ぼかし背景 + 写真全体表示」
- BGMを **開始画像～終了画像** の単位で指定
- BGMは**そっとフェードインして始まり**、曲の変わり目は
  **前曲フェードアウト → 短い無音 → 次曲フェードイン**、最後は**フェードアウトして終わる**
- NVIDIA NVENC が**実際に使えるか**を確かめ、使える環境では GPU エンコードを優先
- NVENC が使えない場合（NVIDIA の GPU が無い PC など）は CPU x264 で書き出す
- **被写体追従カメラ**（実験機能・既定OFF）: 写真に人物の顔か犬が1つだけ写っていれば、
  その方向へゆっくり寄る。判断が曖昧なときは従来方式へ戻る
- スライドショーを作ると、**そのときの設定をJSONで動画の隣に保存**
- 1920x1080 / 3840x2160
- 24 / 30 / 60 fps

## 使用技術

| 用途 | 使用するもの |
| --- | --- |
| GUI | Python 標準の Tkinter (ttk) |
| 画像の読み込み・EXIF回転・リサイズ・背景ぼかし | Pillow |
| フレームのパン／ズーム、クロスフェード合成 | OpenCV + NumPy |
| 動画エンコード、BGM合成 | FFmpeg（PATH優先 / なければ `imageio-ffmpeg` 同梱版） |
| GPUエンコード | FFmpeg の `h264_nvenc`（NVIDIA NVENC） |

映像は「無音のMP4を書き出す」→「BGMを合成して最終MP4にする」の2段階で作成します。
FFmpegへは生フレーム（rawvideo / rgb24）をパイプで渡しています。

## 対応ファイル

- 画像: `.jpg` `.jpeg` `.png` `.webp` `.bmp` `.tif` `.tiff`
- 音声: `.mp3` `.wav` `.m4a` `.aac` `.flac` `.ogg`

## 画面の設定項目

| 項目 | 範囲 | 初期値 |
| --- | --- | --- |
| 写真の間隔 | 2～30秒 | 8.0秒 |
| 写真クロスフェード | 0～4秒 | 1.0秒 |
| ズーム量 | 0～20% | 8% |
| 解像度 | 1920x1080 / 3840x2160 | 1920x1080 |
| FPS | 24 / 30 / 60 | 30 |
| エンコーダ | 自動 / NVENC / CPU x264 | 自動 |
| 縦写真も切らずに見せる（ぼかし背景） | ON / OFF | ON |

作成中は進捗バーが表示され、「中止」ボタンで途中停止できます。

画面が小さい場合やWindowsの表示倍率が高い場合は、メイン画面を縦スクロールできます。
マウスホイールと右端のスクロールバーのどちらでも動きます
（写真やBGMの一覧の上では、その一覧のほうがスクロールします）。

### タイトルカード

| 項目 | 初期値 |
| --- | --- |
| タイトルカードを入れる | ON |
| タイトル / サブタイトル / 日付・補助文字 | （空欄。入力した行だけ描画します） |
| 表示時間 | 5.0秒 |
| 文字フェードイン | 1.5秒 |
| タイトル→写真フェード | 1.0秒 |
| 背景色 | `#FFFFFF` |
| 文字色 | `#333333` |

- 最大3段を中央に配置します。空欄の行は描画しません。
- 文字サイズは画面高さに比例するので、1920x1080でも3840x2160でも同じ見え方になります。
- 日本語は、游ゴシック → メイリオ → MSゴシックの順に
  **日本語の字形を実際に持っているフォント**を選びます。見つからない場合も落ちません。
- 白背景の上に、**文字だけが1.5秒かけてふわっと浮き出て**きます（背景は常に一定）。
  「文字フェードイン」を0秒にすると、従来どおり最初から100%表示になります。
- タイトルカードには**パンもズームもかけません**（完全な静止画）。動くのは文字の濃さだけです。
- タイトルカードは写真ではないので、**写真の番号はタイトルの有無で変わりません**。
  「写真1～写真5 = 曲A」の指定は、タイトルを入れても同じ写真を指します。

### BGM全体設定

曲の入り方・つなぎ方・終わり方は、区間ごとではなく全体で1組だけ指定します。

| 項目 | 初期値 | 意味 |
| --- | --- | --- |
| 冒頭オフセット | 3.0秒 | 動画開始から最初のBGMが鳴り出すまで（冒頭の無音の長さ） |
| 冒頭フェードイン | 1.5秒 | 最初のBGMが満音量になるまで |
| 曲間フェードアウト | 1.5秒 | 前の曲が消えるまで |
| 曲間無音 | 0.7秒 | 曲と曲の間の完全な無音 |
| 曲間フェードイン | 1.5秒 | 次の曲が満音量になるまで |
| 最終フェードアウト | 3.0秒 | 最後の曲を動画末尾で消すまで |

**2曲が同時に鳴ることはありません。** 前の曲が完全に消えてから無音をはさみ、
そのあとで次の曲が入ります。音量が足し算されないので、音割れも起きません。

## 写真の順番

- 写真フォルダーを選ぶと、**ファイル名の自然順**（`1 → 2 → 10`）で読み込みます。
  並べ替えをしなければ、この順番のまま動画になります。
- 「写真の順番」の **並べ替え** ボタンで一覧を開き、上映順を変更できます。
  - 行をドラッグして移動
  - 選んで「上へ」「下へ」（複数選択もまとめて移動できます）
  - 「自然順に戻す」でファイル名順へ戻す
- **元の写真ファイルには一切触れません。** 名前の変更・移動・コピー・
  EXIFの書き換えをしないので、写真フォルダーはそのままです。
  並べ替えるのはアプリが持っている一覧の順番だけです。
- **動画は画面に表示されている順番で作られます。**
- **BGM区間の「写真の番号」も、この並べ替え後の順番を基準にします。**
  たとえば「写真1〜写真5＝曲A」は、常に *上映順の1枚目から5枚目* を意味します。
  並べ替えると、その番号が指す写真も新しい順番に従って変わります。
- 動画の作成中は順番を変更できません。作成開始時点の順番で最後まで作ります。
- 別の写真フォルダーを選び直すと、新しいフォルダーを自然順で読み直します。
  前のフォルダーの並び順も、使う・使わないの指定も残りません。

### 使う写真を選ぶ

同じ一覧で、写真ごとに動画へ使うかどうかも決められます。
**読み込んだ直後はすべて「使う」** なので、何も変えなければ全部の写真が動画になります。

| 上映 | 番号 | ファイル名 |
| --- | --- | --- |
| `[X]` | 1 | IMG_0001.jpg |
| `[X]` | 2 | IMG_0002.jpg |
| `[  ]` | - | IMG_0003.jpg |
| `[X]` | 3 | IMG_0004.jpg |

- 「上映」欄をクリック、または行を選んでスペースキーで切り替えます。
- 「すべて選択」「すべて解除」「選択を反転」でまとめて切り替えられます。
- **使わない写真も一覧からは消えません。** 灰色で残るので、あとで戻せます。
- **番号は「使う写真」だけに 1, 2, 3… と振られます。** 使わない写真は `-` です。
- 使わない写真は、動画に出ないだけでなく、**被写体解析もしません**
  （大量の写真から一部だけ使うときは、解析時間もそのぶん短くなります）。
- 動画の長さにも含まれません。
- **BGM区間の「写真の番号」も、この使う写真だけの上映順を指します。**
- すべて解除したまま作成しようとすると、「使用する写真がありません」と表示して
  作成を始めません。
- もちろん、元の写真ファイルには何もしません。

写真ごとの表示秒数やズーム量といった個別設定はありません。
決められるのは**上映順だけ**で、それ以上の編集は動画編集ソフトに任せる方針です。

## おすすめ解析

写真がたくさんあるときに、**どれを使うか決めるための手がかり**を出す機能です。
写真選択の画面で「おすすめ解析」を押したときだけ動きます。
フォルダーを選んだだけでは動かないので、これまでどおり軽いまま使えます。

やること:

1. **似た写真を探す** — ぶれ具合ではなく、写っているものの見た目で探します
2. **同じ写真の別バージョンをまとめる** — カラー版と白黒版、コピー、
   軽い現像違いは「同じ1枚の写真」として扱います
3. **選ぶときの代替候補をまとめる** — `G01` `G02` … という同じグループIDを付けます
4. **その中でおすすめの星を付ける** — ぶれ・露出・コントラスト・解像度を比べます
5. **最終判断はご自身です** — 表情も、思い出も、このアプリには分かりません

写真を**自動で削除しません**。使う / 使わないも**自動で切り替えません**。
**完全にPCの中だけ**で動きます。

### 「似ている」ではなく「代わりになる」でまとめます

グループは、**同じ場面だからまとめる**のではありません。

> **どれか1枚を選んだら、残りはスライドショーから外してよい**

と思えるくらい、**互いの代わりになる写真**をまとめます。

ですから、同じ場所・同じ人・数分差で撮った写真でも、

- 写っている人数が違う
- ポーズや構図がはっきり違う
- 両方を作品に使いたい

のであれば、**別のグループ**になります。
逆に、カラーと白黒、縦と横、少しの寄り引きの違いだけなら、
同じグループのままです。

実際の写真151枚では、大人数で並んだ集合写真と、
同じ門の下で数人だけ写った集合写真（数分差）が、**別のグループ**になります。

同じ場所で続けて撮った写真のうち、画角が少し動いただけで
見た目の指標が僅かに届かなかったものは、**撮影時刻が数分以内**で、
**同じグループの他の写真とも十分つながっているとき**に限って同じグループにします。
撮影時刻だけでまとめることはありません。撮影時刻が記録されていない写真では、この補いは行いません。

### 同じ写真の別バージョン

カラー版と白黒版は、色で比べると全くの別物に見えます。
そのままだと、本来ひとまとまりの候補を分けてしまいます。

そこで先に、**色を見ずに画像の構造だけ**を比べて、
「同じ1枚の写真の別バージョン」をまとめておきます。
明るさやコントラストを変えても値が動かない比べ方なので、
軽い現像違いも同じ扱いになります。

一覧の「類似」欄に `G05*` のように `*` が付いていたら、
**その写真には別バージョンがある**という印です。

別バージョンと判定しても、**写真は消しません。**
カラー版も白黒版も、両方そのまま一覧に残ります。

星は**推奨度**です。写真の良し悪しでも、写真の価値でもありません。
一覧では「推奨」欄に出ます。

| 推奨度 | 意味 |
| --- | --- |
| ★★★ | 同じグループの中では有力な候補 |
| ★★ | 十分に使えます |
| ★ | 同じグループの中では他の写真を先に見たほうがよい候補、<br>または明確な技術的問題があるため要確認 |

**★はあくまで「同じグループの中での順番」です。**
「使えない写真」でも「壊れた写真」でもありません。
ぶれや露出に問題が無くても、同じグループにもっとくっきりした1枚があれば★になります。
実際、614枚で試したときに★が付いた3枚は、いずれも技術的な問題はなく、
同じグループの中で他を先に見たほうがよい、という理由だけで★でした。

### 星について、はっきりさせておきたいこと

**星は写真の価値を決めるものではありません。** 選ぶときの手がかりです。

この機能は、構図の美しさ・表情・思い出としての価値・物語性を理解していません。
見ているのは、ぶれ具合や明るさといった**測れる範囲のことだけ**です。

多少ぶれていても、多少暗くても、その写真にしかない表情や出来事があれば、
それが一番いい写真かもしれません。**決めるのはご自身です。**

星がいちばん役に立つのは、**代替候補のグループの中**です。
同じ場面の何枚かのうち、どれが技術的にくっきりしているかを示します。
似た写真が無い1枚については、はっきり差があるときだけ★★★にして、
それ以外は★★にしています。どれも同じくらいきれいな写真ばかりのときに、
わずかな差で「こちらがおすすめ」と言い切ってしまわないためです。

笑顔かどうか、かわいいか、目を閉じていないか、といった判断はしていません。

なお現在は、**「同じ場面の中での推奨度」と「技術的な問題の警告」を
★という1つの印にまとめています。**
どちらの理由で★になったのかは、いまの画面では区別できません。
将来この2つを分けて表示することは課題として残しています。

### 画像embedding併用

似た写真をまとめるとき、**画像embedding**も併せて使えます。
「おすすめ解析」の下にある **「画像embeddingを使用」** のチェックで切り替えます。

これまでの pHash・色ヒストグラムだけでは、
**同じ場面なのに少し変わった写真**を取りこぼしていました。

- 少し立ち位置を変えた／向きを変えた
- 縦で撮ったものと横で撮ったもの
- カラーと白黒
- 明るさやトリミングを変えて現像し直したもの

こうした組を拾えるようにするためのものです。
実際の写真614枚で試したところ、まとめられる場面が
30→33、2→12、42→44 と増えました。

**embeddingだけでは決めていません。**
非常に近いとき以外は、これまでの pHash・色ヒストグラムとも
一致していることを条件にしています。
「同じ犬を別の日に撮った写真」のように、
見た目は近くても別の場面のものを混ぜないためです。
これまでの「ほぼ同じ写真」の判定はそのまま残っているので、
**チェックを外せば、これまでとまったく同じ結果**になります。

使うモデル（`models/dinov2_small_embedding.onnx`, 約84MB）については、
[models/README.md](models/README.md) を見てください。

チェックを入れると、**代替候補のまとめ方**（上で説明した2段構え）になります。
外すと、従来のまとめ方（pHash・色ヒストグラムだけ）に戻ります。

- **画像の内容を言葉で理解しているわけではありません。**
  「結婚式」「犬」といった意味づけはしていません。見た目が近いかどうかだけです
- 星の付け方・技術スコアには**一切影響しません**。使うのは似た写真をまとめるところだけです
- これも**PCの中だけ**で動きます。写真も特徴量も外へ出しません
- モデルが無ければ、チェックが押せなくなるだけで、おすすめ解析は従来どおり動きます
- 少し時間が増えます。実測で1枚あたり約44ミリ秒（614枚で約87秒）です

### 勝手なことはしません

- 写真を**削除しません**
- 使う / 使わないを**自動で切り替えません**（★でも使用ONのままです）
- 上映順を**自動で変えません**（★★★を上へ動かしたりしません）
- グループ順に並べ替えたりもしません

解析しても、ご自身が何も変えなければ、できる動画はまったく同じです。

### そのほか

- 使わない設定にした写真も解析します（選び直すときの比べる相手になるため）
- 解析中も画面は固まりません。途中で中止できます
- 一度解析した写真は、同じアプリを開いている間は結果を使い回します
- **完全にPCの中だけで動きます。** 写真を外部へ送りません。
  クラウドAPIもLLMも使わず、使うのは Pillow / NumPy / OpenCV / ONNX Runtime だけです。
  モデルは同梱のファイルを読むだけで、実行時のダウンロードもありません

## 被写体追従カメラ（実験機能）

写真の中に被写体が**はっきり1つだけ**写っているとき、そちらへカメラを向けます。
GUIの「カメラワーク」で切り替えます。**初期値は従来方式**なので、
何も変えなければ今までと同じ動画ができます。

| 写っているもの | 動き |
| --- | --- |
| 人物の顔が1つだけ | その顔の方向へゆっくり寄る |
| 犬が1頭だけ | 犬の**体の上側**（頭・肩・背中寄り）へ寄る |
| 顔も犬も無い | 従来方式（ランダム方向のパン） |
| 顔が2つ以上 | 従来方式 |
| 犬が2頭以上 | 従来方式 |
| 人と犬が一緒 | 従来方式 |

**主役を勝手に決めません。** 候補が複数あるとき、一番大きい顔や一番中央の犬を
選ぶようなことはせず、実績のある従来方式へ戻します。

その他の性質:

- パンの方向だけが変わります。ズーム量・速度・smoothstep・写真クロスフェードは従来のままです。
- 写真の最初から被写体に寄った状態にはなりません。全体を見せてから、
  8秒かけてゆっくり寄っていきます。
- 被写体を必ず画面中央へ持ってくるわけではありません。ズームで生まれた余白の
  範囲内だけで動くので、画面の外や黒帯が見えることはありません。
- 検出は写真1枚につき1回だけ、動画を作る前の「被写体解析」でまとめて行います。

### プライバシー

- **これは顔認識ではありません。** 誰であるかは判定しません。
  「顔がどこにあるか」だけを見ます。個人識別・顔embedding・照合用データベースは作りません。
- 犬についても、犬種の判定や個体の識別はしません。位置だけを使います。
- **完全にPC内で完結します。** 写真を外部へ送信しません。クラウドAPIも使いません。
  実行中にインターネットへ接続することはなく、モデルを自動ダウンロードすることもありません。

### 使うモデル

配布 ZIP には次の 2 つのモデルが同梱されています（ソースを GitHub から取得した場合の置き方は
[models/README.md](models/README.md)）。

| 用途 | モデル | バージョン | ライセンス |
| --- | --- | --- | --- |
| 人物の顔 | YuNet (`face_detection_yunet_2023mar.onnx`) | 2023mar | MIT / Shiqi Yu |
| 犬 | YOLOX (`object_detection_yolox_2022nov.onnx`) | 2022nov | Apache-2.0 / Megvii Inc. |

どちらも [OpenCV Zoo](https://github.com/opencv/opencv_zoo) の配布物で、OpenCV DNN から使います。
PyTorch や TensorFlow は必要ありません。詳細は [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) にあります。

モデルが無い場合は、その旨がGUIに表示され、**従来カメラワークはそのまま使えます。**

## 設定の保存

スライドショーを作ると、できた動画と同じ場所へ
`<動画名>_settings.json` という設定ファイルを自動で保存します。

あとから「この動画はどの設定で作ったか」を見返せるようにするためのものです。
写真フォルダーと枚数、解像度・FPS・写真の間隔・クロスフェード・ズーム量・
エンコーダ・カメラワーク、タイトルカードの全項目、BGM全体設定、
BGM区間（開始/終了の写真番号とファイル名、曲のパス）が入ります。

設定ファイルには、**写真フォルダー・書き出し先・曲の場所（PC 上のパス）が入ります。**
設定ファイルを人に渡すときは注意してください（動画そのものには入りません）。

実際に上映した順番を `image_order`、一覧の全部と使ったかどうかを `images`
（`filename` と `included`）として記録します。この 2 つはファイル名だけです。

おすすめ解析を実行していた場合は、`photo_recommendations` として
写真ごとのグループID・星・技術スコアも記録します。
画像embeddingを使っていた場合は、`recommendation_engine` として
使ったモデル名とrevisionも残ります（どの版で解析したか後から分かるように）。
実行していなければ何も増えないので、これまでの設定ファイルと同じ形のままです。

被写体追従ONで作った場合は、写真ごとの解析結果
（顔の数・犬の数・どちらへ寄ったか・目標座標）も記録されます。

## BGM区間の指定例

写真が

- IMG_0001.jpg ～ IMG_0032.jpg
- IMG_0033.jpg ～ IMG_0068.jpg
- IMG_0069.jpg ～ IMG_0105.jpg

なら、

- IMG_0001 ～ IMG_0032 = 曲A
- IMG_0033 ～ IMG_0068 = 曲B
- IMG_0069 ～ IMG_0105 = 曲C

のように登録できます。

境界（IMG_0033が出る時刻）では、曲Aが1.5秒かけて消え、0.7秒の無音をはさんでから、
曲Bが1.5秒かけて入ってきます。

補足:

- BGM区間どうしを重ねて指定することはできません（事故防止のためエラーになります）
- 区間を指定していない写真は無音です。前後の曲を勝手に引き延ばしません
- 最後の区間が動画の最後まで届いていない場合は、その区間の終わりで消えてそのまま無音です
- BGMが区間より短い場合は自動でループします
- 区間が短くてフェードと無音が入りきらない場合は、自動的に縮めて安全に収めます。
  それでも0.3秒未満にしかならない区間は、鳴らさずに無音にします
- 音声は AAC 256kbps で書き出します

## 最初に勧める設定

- タイトルカード: ON / 表示時間 5.0秒 / 文字フェードイン 1.5秒 / タイトル→写真 1.0秒
- 写真の間隔: 8.0秒
- 写真クロスフェード: 1.0秒
- ズーム量: 8%
- 解像度: 1920x1080
- FPS: 30
- エンコーダ: 自動
- BGM全体設定: 初期値のまま（3.0 / 1.5 / 1.5 / 0.7 / 1.5 / 3.0）

この初期値だと、冒頭は次のように進みます。

| 時刻 | 起きること |
| --- | --- |
| 0.0秒 | 白背景のみ表示。文字は0%、音も無音 |
| 0.0〜1.5秒 | タイトル文字が0%から100%へフェードイン |
| 1.5〜3.0秒 | タイトルを完全表示したまま、無音で見せる |
| 3.0秒 | 最初のBGMが音量0で始まる |
| 3.0〜4.5秒 | 1.5秒かけてフェードイン |
| 4.5秒 | 通常音量 |
| 5.0秒 | タイトルカード終了、写真1へ |

150枚なら約20分です（タイトルカードのぶん、さらに5秒加わります）。

動画の長さは **タイトル表示時間 + 写真枚数 × 写真の間隔** です。
写真クロスフェードやタイトル→写真フェードで長さが伸びることはありません。

## 既知の制限

- Windows 11 向けです。ほかの OS では確認していません
- Python が必要です（exe やインストーラーの形ではありません）。確認済みは Python 3.13 だけです
- 写真ごとに表示時間を変えることはできません（決められるのは全体で 1 つの「写真の間隔」）
- BGM のテンポ（BPM）に合わせた切り替えはありません。BGM は必ず曲の先頭から使います
- 画面からの BGM の音量調整・リミッターはありません（元の曲の音量のまま合成します）
- 被写体の検出は完全ではありません。顔や犬を見落とすこと、関係のないものを拾うことがあります
- 被写体追従カメラ（実験機能）は顔・犬の方向へ寄るだけです。全身や衣装の端が画面の外へ出ることがあります。
  人物全体・犬全体をできるだけ画面に残す `subject_safe` は、今の版では CLI / Project JSON からだけ使えます
  （それも、検出できた範囲をできるだけ残す機能で、ドレスの裾などを必ず全部残すものではありません）
- つなぎ方の種類（カット・暗転・スライド）と音声のリミッターも、今の版では CLI / Project JSON からだけです。
  画面から作る動画は、これまでどおりクロスフェードです

## 開発者向け（AI・自動化から使う）

**通常の利用（画面で動画を作る）には、この節の内容は一切不要です。**

画面を使わずに、写真の一覧・おすすめ解析・曲の測定・上映計画（Project JSON）の組み立て・書き出しを
呼び出せる JSON CLI（`pmm_cli.py`）と Core API（`pmm_core.py`）が入っています。
写真を選ぶ・並べる・曲を選ぶといった判断は呼び出す側（人や AI）が行い、PhotoMovieMaker はそのとおりに
確実に書き出すだけです。**PhotoMovieMaker の中に AI は入っていません。**

- 使い方: [docs/DEVELOPER.md](https://github.com/pon-papa/PhotoMovieMaker_GPU/blob/main/docs/DEVELOPER.md)
- AI（SI）が作品を組み立てるための部品と約束ごと:
  [docs/SI_DIRECTOR_V1.md](https://github.com/pon-papa/PhotoMovieMaker_GPU/blob/main/docs/SI_DIRECTOR_V1.md)・
  [docs/SI_DIRECTOR_V2.md](https://github.com/pon-papa/PhotoMovieMaker_GPU/blob/main/docs/SI_DIRECTOR_V2.md)

作者の記事で行った「AI が写真を選ぶ・124 曲を比べる・Project を組み立てる」は、この CLI を作者の実験用の
AI 連携環境（非公開）から呼び出したものです。その連携環境は配布物に含まれません。
このアプリの通常利用に、それらは必要ありません。
