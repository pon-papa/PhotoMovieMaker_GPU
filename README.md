# PhotoMovieMaker GPU

Windows 11 で、写真フォルダーから記念映像（MP4）を作る小型GUIアプリです。

バージョン: v0.1.1

## 主な機能

- 動画の先頭に**タイトルカード**を自動生成（アプリ内部で作るので、写真フォルダーは汚しません）
- 画像をファイル名の自然順で並べる。**アプリ上で上映順の並べ替えと、使う写真の選択ができる**
- 初期値は **8秒ごとに次の写真へ**
- ゆっくりランダム方向へパン
- 徐々にズームイン
- 写真間は初期値1秒クロスフェード
- 縦写真は「ぼかし背景 + 写真全体表示」
- BGMを **開始画像～終了画像** の単位で指定
- BGMは**そっとフェードインして始まり**、曲の変わり目は
  **前曲フェードアウト → 短い無音 → 次曲フェードイン**、最後は**フェードアウトして終わる**
- NVIDIA NVENC を自動検出し、利用できる環境ではGPUエンコードを優先
- NVENCが使えない場合はCPU x264へ自動フォールバック
- **被写体追従カメラ**（実験機能・既定OFF）: 写真に人物の顔か犬が1つだけ写っていれば、
  その方向へゆっくり寄る。判断が曖昧なときは従来方式へ戻る
- スライドショーを作ると、**そのときの設定をJSONで動画の隣に保存**
- 1920x1080 / 3840x2160
- 24 / 30 / 60 fps

## 使用技術

| 用途 | 使用するもの |
| --- | --- |
| GUI | Python 標準の Tkinter (ttk) |
| 画像の読み込み・EXIF回転・リサイズ・背景ぼかし | Pillow |
| フレームのパン／ズーム、クロスフェード合成 | OpenCV + NumPy |
| 動画エンコード、BGM合成 | FFmpeg（PATH優先 / なければ `imageio-ffmpeg` 同梱版） |
| GPUエンコード | FFmpeg の `h264_nvenc`（NVIDIA NVENC） |

映像は「無音のMP4を書き出す」→「BGMを合成して最終MP4にする」の2段階で作成します。
FFmpegへは生フレーム（rawvideo / rgb24）をパイプで渡しています。

## 動作環境

- Windows 11
- Python 3.11 / 3.12 / 3.13（3.13.14 で動作確認済み）
- NVIDIA GPU（NVENC対応なら自動でGPUエンコード。無くてもCPUで動作します）

作者の確認環境:

- Xeon E5-2698 v4 ×2
- NVIDIA RTX A2000 6GB
- RAM 64GB

この構成では、まず 1920x1080 / 30fps / エンコーダ「自動」で試してください。
A2000のNVENCが検出されれば映像圧縮はGPU側で行います。
パン・ズーム処理にはOpenCVを使用し、利用可能なCPUスレッドも使います。

## セットアップ

1. Python 3.11 / 3.12 / 3.13 のいずれかをインストール
2. `setup.bat` をダブルクリック（`requirements.txt` の依存をインストール）
3. `run.bat` をダブルクリック（アプリ起動）

依存パッケージ（`requirements.txt`）:

```
pillow>=10.0
numpy>=1.26
opencv-python>=4.9,<6
imageio-ffmpeg>=0.5
```

FFmpegは、PATH上にインストール済みのものがあればそれを優先します。
なければ `imageio-ffmpeg` の同梱FFmpegを使います。

### NVENCについて

「自動」で `h264_nvenc` が検出されればNVENCを使います。
もしNVENCが検出されない場合は、Windows用のNVENC対応FFmpegを別途インストールして
PATHを通せば利用できます。

## 対応ファイル

- 画像: `.jpg` `.jpeg` `.png` `.webp` `.bmp` `.tif` `.tiff`
- 音声: `.mp3` `.wav` `.m4a` `.aac` `.flac` `.ogg`

## 画面の設定項目

| 項目 | 範囲 | 初期値 |
| --- | --- | --- |
| 写真の間隔 | 2～30秒 | 8.0秒 |
| 写真クロスフェード | 0～4秒 | 1.0秒 |
| ズーム量 | 0～20% | 8% |
| 解像度 | 1920x1080 / 3840x2160 | 1920x1080 |
| FPS | 24 / 30 / 60 | 30 |
| エンコーダ | 自動 / NVENC / CPU x264 | 自動 |
| 縦写真も切らずに見せる（ぼかし背景） | ON / OFF | ON |

作成中は進捗バーが表示され、「中止」ボタンで途中停止できます。

画面が小さい場合やWindowsの表示倍率が高い場合は、メイン画面を縦スクロールできます。
マウスホイールと右端のスクロールバーのどちらでも動きます
（写真やBGMの一覧の上では、その一覧のほうがスクロールします）。

### タイトルカード

| 項目 | 初期値 |
| --- | --- |
| タイトルカードを入れる | ON |
| タイトル / サブタイトル / 日付・補助文字 | （空欄。入力した行だけ描画します） |
| 表示時間 | 5.0秒 |
| 文字フェードイン | 1.5秒 |
| タイトル→写真フェード | 1.0秒 |
| 背景色 | `#FFFFFF` |
| 文字色 | `#333333` |

- 最大3段を中央に配置します。空欄の行は描画しません。
- 文字サイズは画面高さに比例するので、1920x1080でも3840x2160でも同じ見え方になります。
- 日本語は、游ゴシック → メイリオ → MSゴシックの順に
  **日本語の字形を実際に持っているフォント**を選びます。見つからない場合も落ちません。
- 白背景の上に、**文字だけが1.5秒かけてふわっと浮き出て**きます（背景は常に一定）。
  「文字フェードイン」を0秒にすると、従来どおり最初から100%表示になります。
- タイトルカードには**パンもズームもかけません**（完全な静止画）。動くのは文字の濃さだけです。
- タイトルカードは写真ではないので、**写真の番号はタイトルの有無で変わりません**。
  「写真1～写真5 = 曲A」の指定は、タイトルを入れても同じ写真を指します。

### BGM全体設定

曲の入り方・つなぎ方・終わり方は、区間ごとではなく全体で1組だけ指定します。

| 項目 | 初期値 | 意味 |
| --- | --- | --- |
| 冒頭オフセット | 3.0秒 | 動画開始から最初のBGMが鳴り出すまで（冒頭の無音の長さ） |
| 冒頭フェードイン | 1.5秒 | 最初のBGMが満音量になるまで |
| 曲間フェードアウト | 1.5秒 | 前の曲が消えるまで |
| 曲間無音 | 0.7秒 | 曲と曲の間の完全な無音 |
| 曲間フェードイン | 1.5秒 | 次の曲が満音量になるまで |
| 最終フェードアウト | 3.0秒 | 最後の曲を動画末尾で消すまで |

**2曲が同時に鳴ることはありません。** 前の曲が完全に消えてから無音をはさみ、
そのあとで次の曲が入ります。音量が足し算されないので、音割れも起きません。

## 写真の順番

- 写真フォルダーを選ぶと、**ファイル名の自然順**（`1 → 2 → 10`）で読み込みます。
  並べ替えをしなければ、この順番のまま動画になります。
- 「写真の順番」の **並べ替え** ボタンで一覧を開き、上映順を変更できます。
  - 行をドラッグして移動
  - 選んで「上へ」「下へ」（複数選択もまとめて移動できます）
  - 「自然順に戻す」でファイル名順へ戻す
- **元の写真ファイルには一切触れません。** 名前の変更・移動・コピー・
  EXIFの書き換えをしないので、写真フォルダーはそのままです。
  並べ替えるのはアプリが持っている一覧の順番だけです。
- **動画は画面に表示されている順番で作られます。**
- **BGM区間の「写真の番号」も、この並べ替え後の順番を基準にします。**
  たとえば「写真1〜写真5＝曲A」は、常に *上映順の1枚目から5枚目* を意味します。
  並べ替えると、その番号が指す写真も新しい順番に従って変わります。
- 動画の作成中は順番を変更できません。作成開始時点の順番で最後まで作ります。
- 別の写真フォルダーを選び直すと、新しいフォルダーを自然順で読み直します。
  前のフォルダーの並び順も、使う・使わないの指定も残りません。

### 使う写真を選ぶ

同じ一覧で、写真ごとに動画へ使うかどうかも決められます。
**読み込んだ直後はすべて「使う」** なので、何も変えなければ全部の写真が動画になります。

| 上映 | 番号 | ファイル名 |
| --- | --- | --- |
| `[X]` | 1 | IMG_0001.jpg |
| `[X]` | 2 | IMG_0002.jpg |
| `[  ]` | - | IMG_0003.jpg |
| `[X]` | 3 | IMG_0004.jpg |

- 「上映」欄をクリック、または行を選んでスペースキーで切り替えます。
- 「すべて選択」「すべて解除」「選択を反転」でまとめて切り替えられます。
- **使わない写真も一覧からは消えません。** 灰色で残るので、あとで戻せます。
- **番号は「使う写真」だけに 1, 2, 3… と振られます。** 使わない写真は `-` です。
- 使わない写真は、動画に出ないだけでなく、**被写体解析もしません**
  （大量の写真から一部だけ使うときは、解析時間もそのぶん短くなります）。
- 動画の長さにも含まれません。
- **BGM区間の「写真の番号」も、この使う写真だけの上映順を指します。**
- すべて解除したまま作成しようとすると、「使用する写真がありません」と表示して
  作成を始めません。
- もちろん、元の写真ファイルには何もしません。

写真ごとの表示秒数やズーム量といった個別設定はありません。
決められるのは**上映順だけ**で、それ以上の編集は動画編集ソフトに任せる方針です。

## 被写体追従カメラ（実験機能）

写真の中に被写体が**はっきり1つだけ**写っているとき、そちらへカメラを向けます。
GUIの「カメラワーク」で切り替えます。**初期値は従来方式**なので、
何も変えなければ今までと同じ動画ができます。

| 写っているもの | 動き |
| --- | --- |
| 人物の顔が1つだけ | その顔の方向へゆっくり寄る |
| 犬が1頭だけ | 犬の**体の上側**（頭・肩・背中寄り）へ寄る |
| 顔も犬も無い | 従来方式（ランダム方向のパン） |
| 顔が2つ以上 | 従来方式 |
| 犬が2頭以上 | 従来方式 |
| 人と犬が一緒 | 従来方式 |

**主役を勝手に決めません。** 候補が複数あるとき、一番大きい顔や一番中央の犬を
選ぶようなことはせず、実績のある従来方式へ戻します。

その他の性質:

- パンの方向だけが変わります。ズーム量・速度・smoothstep・写真クロスフェードは従来のままです。
- 写真の最初から被写体に寄った状態にはなりません。全体を見せてから、
  8秒かけてゆっくり寄っていきます。
- 被写体を必ず画面中央へ持ってくるわけではありません。ズームで生まれた余白の
  範囲内だけで動くので、画面の外や黒帯が見えることはありません。
- 検出は写真1枚につき1回だけ、動画を作る前の「被写体解析」でまとめて行います。

### プライバシー

- **これは顔認識ではありません。** 誰であるかは判定しません。
  「顔がどこにあるか」だけを見ます。個人識別・顔embedding・照合用データベースは作りません。
- 犬についても、犬種の判定や個体の識別はしません。位置だけを使います。
- **完全にPC内で完結します。** 写真を外部へ送信しません。クラウドAPIも使いません。
  実行中にインターネットへ接続することはなく、モデルを自動ダウンロードすることもありません。

### 使うモデル

`models` フォルダーへ次の2つを置くと使えるようになります。置き方は
[models/README.md](models/README.md) を参照してください。

| 用途 | モデル | バージョン | ライセンス |
| --- | --- | --- | --- |
| 人物の顔 | YuNet (`face_detection_yunet_2023mar.onnx`) | 2023mar | MIT / Shiqi Yu |
| 犬 | YOLOX (`object_detection_yolox_2022nov.onnx`) | 2022nov | Apache-2.0 / Megvii Inc. |

どちらも [OpenCV Zoo](https://github.com/opencv/opencv_zoo) の配布物で、OpenCV DNN から使います。
PyTorch や TensorFlow は必要ありません。詳細は [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) にあります。

モデルが無い場合は、その旨がGUIに表示され、**従来カメラワークはそのまま使えます。**

## 設定の保存

スライドショーを作ると、できた動画と同じ場所へ
`<動画名>_settings.json` という設定ファイルを自動で保存します。

あとから「この動画はどの設定で作ったか」を見返せるようにするためのものです。
写真フォルダーと枚数、解像度・FPS・写真の間隔・クロスフェード・ズーム量・
エンコーダ・カメラワーク、タイトルカードの全項目、BGM全体設定、
BGM区間（開始/終了の写真番号とファイル名、曲のパス）が入ります。

実際に上映した順番を `image_order`、一覧の全部と使ったかどうかを `images`
（`filename` と `included`）として記録します。どちらもファイル名だけで、
絶対パスは残しません。

被写体追従ONで作った場合は、写真ごとの解析結果
（顔の数・犬の数・どちらへ寄ったか・目標座標）も記録されます。

## BGM区間の指定例

写真が

- IMG_0001.jpg ～ IMG_0032.jpg
- IMG_0033.jpg ～ IMG_0068.jpg
- IMG_0069.jpg ～ IMG_0105.jpg

なら、

- IMG_0001 ～ IMG_0032 = 曲A
- IMG_0033 ～ IMG_0068 = 曲B
- IMG_0069 ～ IMG_0105 = 曲C

のように登録できます。

境界（IMG_0033が出る時刻）では、曲Aが1.5秒かけて消え、0.7秒の無音をはさんでから、
曲Bが1.5秒かけて入ってきます。

補足:

- BGM区間どうしを重ねて指定することはできません（事故防止のためエラーになります）
- 区間を指定していない写真は無音です。前後の曲を勝手に引き延ばしません
- 最後の区間が動画の最後まで届いていない場合は、その区間の終わりで消えてそのまま無音です
- BGMが区間より短い場合は自動でループします
- 区間が短くてフェードと無音が入りきらない場合は、自動的に縮めて安全に収めます。
  それでも0.3秒未満にしかならない区間は、鳴らさずに無音にします
- 音声は AAC 256kbps で書き出します

## 最初に勧める設定

- タイトルカード: ON / 表示時間 5.0秒 / 文字フェードイン 1.5秒 / タイトル→写真 1.0秒
- 写真の間隔: 8.0秒
- 写真クロスフェード: 1.0秒
- ズーム量: 8%
- 解像度: 1920x1080
- FPS: 30
- エンコーダ: 自動
- BGM全体設定: 初期値のまま（3.0 / 1.5 / 1.5 / 0.7 / 1.5 / 3.0）

この初期値だと、冒頭は次のように進みます。

| 時刻 | 起きること |
| --- | --- |
| 0.0秒 | 白背景のみ表示。文字は0%、音も無音 |
| 0.0〜1.5秒 | タイトル文字が0%から100%へフェードイン |
| 1.5〜3.0秒 | タイトルを完全表示したまま、無音で見せる |
| 3.0秒 | 最初のBGMが音量0で始まる |
| 3.0〜4.5秒 | 1.5秒かけてフェードイン |
| 4.5秒 | 通常音量 |
| 5.0秒 | タイトルカード終了、写真1へ |

150枚なら約20分です（タイトルカードのぶん、さらに5秒加わります）。

動画の長さは **タイトル表示時間 + 写真枚数 × 写真の間隔** です。
写真クロスフェードやタイトル→写真フェードで長さが伸びることはありません。

## 注意

初版では人物の顔認識まではしていません。
そのためパン方向は「上品に見えやすい方向セット」から選びます。
パン方向は固定シードで決めているため、同じ素材なら同じ結果になります。
